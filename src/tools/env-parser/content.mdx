## 为什么需要 .env 与 JSON 互转

后端项目里配置习惯写在 `.env`（`KEY=VALUE` 每行一个），但配置中心、CI、前端注入常常要 JSON。两边来回手抄既慢又容易把引号、注释、特殊字符搞坏。

本工具在 `.env` 文本和 JSON 对象之间双向转换：解析时自动去 `export ` 前缀、去 `#` 注释、剥离多余引号；序列化时把 JSON 漂亮地写回 `.env` 格式。

## 概念与公式

`.env` 是「每行一个 `KEY=VALUE`」的纯文本格式（dotenv 约定）：

- `#` 开头为注释，空行忽略；
- 值可用单/双引号包裹，也可裸写；
- 部分项目用 `export KEY=VALUE`（shell 风格）。
- JSON 是键值对的树形结构，支持嵌套对象 / 数组。

转换规则：解析时按行切分 → 跳过注释与空行 → 以首个 `=` 拆键和值 → 去引号 → 还原成 JSON 对象（纯扁平，不猜测嵌套）；序列化时把 JSON 的扁平键逐行写成 `KEY=VALUE`。

## 细分场景

- **本地 ↔ 云端配置**：把 `.env` 导成 JSON 推到配置中心，或反向拉回本地。
- **CI 注入**：把 JSON 变量拆成 `.env` 供容器读取。
- **快速预览**：把一堆环境变量变成可读的 JSON 看结构。

## 怎么用本工具

在左侧贴 `.env` 或 JSON，选择方向（`.env → JSON` 或 `JSON → .env`），结果即时出现在右侧。解析失败会提示哪一行格式异常。复制按钮一键带走。

## 常见场景与实例

**例：解析**
```
# 数据库
DB_HOST=127.0.0.1
DB_PORT=5432
export API_KEY="abc123"
```
→ `{"DB_HOST":"127.0.0.1","DB_PORT":"5432","API_KEY":"abc123"}`（注释、export、引号都被正确处理）。
