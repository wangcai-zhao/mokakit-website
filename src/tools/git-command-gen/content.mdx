## Git 命令生成是什么

Git 的命令多、参数杂，而撤销类和强推类命令一旦敲错就是事故。按场景生成并标注风险，比凭记忆手敲靠谱。

## 这个工具能做什么

- 十四个常见场景，覆盖撤销、分支、同步、发版
- 按安全 / 需确认 / 有风险三档标注
- 填参数即可生成完整命令序列
- 危险命令附带执行前的备份提醒

## 怎么使用（输入说明）

1. **点选你要做的事**
2. **填分支名、提交信息等参数**
3. **看清风险标注**
4. **复制命令**

## 使用时的几个注意点

- 带 --hard 和 --force 的命令务必先看懂
- 强推优先用 --force-with-lease
- 公共分支不要 rebase

## 实例

「撤回上一次提交」生成 git reset --soft HEAD~1，风险标注为安全。

## 常见问题 FAQ

**Q：reset --soft 和 --hard 有什么区别？**

A：--soft 只把 HEAD 指针退回去，改动还留在工作区，可以重新提交；--hard 连改动一起丢弃，找不回来。刚提交完发现写错了用 --soft。

**Q：为什么推荐 --force-with-lease 而不是 --force？**

A：--force 会无条件覆盖远程分支，可能把同事刚推的提交抹掉。--force-with-lease 会先检查远程有没有你不知道的新提交，有就拒绝推送，安全得多。

**Q：rebase 什么时候不该用？**

A：已经推送到公共分支、且别人可能基于它继续开发的提交不要 rebase。rebase 会改写历史，其他人的本地仓库会和远程对不上。
