## 我遇到的具体问题

年初给自己定了规矩：每天下班前写一条日报，记今天干了啥。前两周挺好，像打卡。到第 20 天那天，我盯着空白的文档愣了五分钟，脑子里一片空白——干了啥？好像做了点东西，但又说不清。

硬挤出来的日报全是"推进了 XX 项目""处理了若干需求"这种废话。我自己都不想看，更别提给老板看。

## 为什么这事值得自动化

日报的本质是"记录"，不是"创作"。我每天在 Git 上提交的代码、改的文件，本身就是最诚实的工作记录。手写是在用脑子重新概括一遍已经发生过的事，纯属重复劳动。

我算过：每天写日报平均十二分钟，一个月就是四五个小时，一年小六十小时，全花在"把提交记录翻译成人话"上。这活交给机器明显更合适。

## 我是怎么用 WorkBuddy 做的

我搭了个定时任务（WorkBuddy 的自动化，每周五下午跑），让它拉取我这周的 Git 提交，自动生成周报草稿。

具体链路是这样的：先用 [变更日志生成器](/tools/changelog-gen/) 把一堆 commit 按"功能/修复/其他"归类成清单，再用 [提交信息生成器](/tools/commit-gen/) 帮我回头补几条不规范的提交说明，最后让 WorkBuddy 把这些拼成一段有结构的周报。

我每周五收到草稿，改两句话就发出去，全程不到半小时。

## 中间卡在哪 & 怎么绕过去

最大的坑是：自动化依赖"提交记录干净"。我前面那些 commit message 写得跟谜语一样（"fix""update""改了点"），机器再聪明也概括不出东西。

绕过去的办法是反过来——用 [提交信息生成器](/tools/commit-gen/) 立个规矩：以后提交前先让它把改动写成规范的 message。提交记录一规范，周报生成质量直接上一个台阶。相当于把"写日报"的成本前置到了"写提交"那一刻，但那本来就是要写的，不亏。

另一个坑：定时任务第一次跑时，我忘了给它读仓库的权限，它拉不到提交。在配置里把仓库路径授权上就好了。

## 顺带的几个发现

周报自动化之后，我顺手加了 [工时统计](/tools/weekly-hours/) 这个小工具，把每天在哪类任务上花了多久记下来。月底复盘时发现，我竟然有快三成时间耗在"临时打断"上——这数据手写日报根本看不出来。

现在周报不只是交差，还成了我调整工作节奏的依据。

## 你也可以这样用

如果你也在用 Git，别从零写周报。先让工具把提交归类成清单，再让 AI 润色成叙述。关键是把"写提交"这件事做规范，后面的自动化才转得动。

## 常见问题

**Q：提交记录太乱，生成出来的周报也没法看？**
先治理提交信息。用提交信息生成器把历史上的谜语 message 补规范，往后立规矩，两三天就能见效。

**Q：我不是开发，没有 Git 提交怎么办？**
思路一样：找你每天本来就留下的"记录"（任务系统的状态变更、文档的修改时间），让 AI 基于这些生成，而不是凭空编。

**Q：定时任务会漏跑吗？**
WorkBuddy 的自动化到点自动触发，跑完有记录。我每周五瞄一眼产物就行，没漏过。
