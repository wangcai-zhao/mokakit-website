## 开源协议（License）是什么

**开源协议**是一份法律文件，规定了别人在「使用、复制、修改、再分发」你的代码时**能做什么、不能做什么**。它把「开源」从一句口号变成有约束力的规则：你选了某个协议，就等于向全世界宣布「在遵守这些条款的前提下，你可以免费用我的代码」。

没有协议的文件，法律上默认是「保留所有权利」——别人哪怕想引用一行，理论上都需要你单独授权。所以**只要你想让别人用，就应该显式选一个协议**。

## 为什么不能随便选

不同协议的「开放程度」差异巨大：

- **宽松协议（MIT / Apache / BSD / ISC / Unlicense）**：别人可以拿去闭源商用，只要保留版权声明。对采用方最友好，传播最快。
- **弱 Copyleft（MPL / LGPL）**：你修改的那部分必须开源，但可以和闭源代码组合。适合做「希望被广泛集成、又想保护自己修改」的库。
- **强 Copyleft（GPL / AGPL）**：基于它的衍生作品（甚至 AGPL 的网络服务）都必须以相同协议开源。适合强调「自由」、不希望被闭源吸收的项目。

选错协议可能带来法律风险：比如公司项目误用了 GPL 代码，可能被要求公开整个产品源码。

## 怎么快速选

1. **能不能闭源商用？**
   - 能 → 想要专利保护选 **Apache-2.0**，否则选 **MIT / ISC / BSD / Unlicense**。
   - 不能（希望衍生作品也开源）→ 看下一步。
2. **开源力度要多强？**
   - 只要求「被修改的文件开源」、允许和闭源组合 → **MPL-2.0 / LGPL-3.0**。
   - 要求「所有衍生作品甚至网络服务都开源」 → **GPL-3.0 / AGPL-3.0**。

本工具的「帮我选」会按你的答案直接给出推荐，省去反复查文档。

## 生成的 LICENSE 怎么用

1. 在工具里填好**年份**和**版权所有者**（个人或组织名），右侧会自动替换占位符。

3. 在 `README` 顶部加一行声明，例如：`Licensed under the MIT License`。

> 说明：GPL / AGPL 等超长协议，本工具生成的 LICENSE 文件中会指向 **GNU 官方权威全文**，请以下载时文件内的链接为准；其余协议均为可直接使用的完整文本。

## 几个常见误区

- **「不写协议 = 随便用」是错的**：没协议 = 保留所有权利，别人用需要单独授权。
- **「MIT 不能商用」是错的**：MIT 明确允许商用，只需保留版权声明。
- **「用了 GPL 我就不能赚钱」是错的**：GPL 不禁止收费，只是要求你分发的衍生作品也开源。
- **「AGPL 只影响分发」是错的**：AGPL 把「通过网路提供服务」也视为需要开源的情形，纯 SaaS 服务端也要当心。
