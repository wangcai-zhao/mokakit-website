title: CloudBase 免费版能不能跑 MCP？一次成本实测
date: 2026-09-11

---

MCP 服务想上云，第一反应扔 CloudBase 体验版——免费，还送 3000 资源点/月，看着挺宽裕。结果真算一笔账，差点翻车。

MCP 服务要常驻还是按需？我先按"常驻"算：开 0.25C / 0.5G 够用了。CloudBase 单价 CPU 55 点/(核·时)、内存 32 点/(GB·时)。一个月跑下来：CPU 180 核时 × 55 = 9900 点，内存 360 GB时 × 32 = 11520 点，加起来 21420 点/月。体验版那 3000 点，只够撑约 4 天。直接否掉，常驻这条路在免费版走不通。

换个思路，走 HTTP 云函数，按次计费。MCP 本来就是请求-响应模型，一次调用算完就走，跟云函数天然契合。按 512MB / 300ms / 50KB 响应估，单次约 0.056 点。一天 100 次才 5.6 点，一个月 170 点，体验版完全扛得住。资源点单价参考：云函数 13.3 点/万次 + 0.11108 点/GBs，外网出流量 800 点/GB。

结论很明确：体验版下 MCP 只能走 HTTP 云函数，别想常驻。好在 MCP 不是长连接，按请求付费反而更省钱，不用为"一直开着"买单。

附带一个没完全确认的点：个人版云函数超时传言是 3 秒，MCP 单次计算远到不了这个量，够用。但上云前得把 session 设计成无状态——云函数多并发时内存里的 session 会丢，得容忍重新 initialize，或者干脆不放 session。

免费版不是不能玩 MCP，是得按"请求-响应"的姿势玩。等以后升个人版（¥19.9/月）能绑域名、开云托管，再考虑常驻形态。现在这步先把 HTTP 云函数跑通就行。
