## ikxin/kms-tools 深度调研（只出报告，未改代码）

- **产出**：`_reports/kms-tools-分析报告-2026-10-23.md`；原始源码留 `_kms_src/`（34 个文件，文件名用 `~` 代替 `/`）。
- **项目事实**：764★ / MIT / v2.2.0 / 477 commits / 118 文件。Nuxt4 + Vue3 + Arco + Tailwind4 + Nitro + Drizzle(D1) + ECharts + 18 语言 i18n。三功能：激活脚本生成（纯前端）/ KMS 检测 / 服务器监控（需后端）。
- **核心发现：`node-vlmcs` 是纯 TS 手写 KMS 客户端**（零运行时依赖，已发 npm 1.0.1，MIT）。含 `rpc.ts`（MS-RPCE bind/NDR32/NDR64/BTFN）、`kms.ts`（V4 236+CMAC / V5V6 260+AES-CBC、V6 HMAC 按 ~4.11h 时间槽派生子密钥）、`crypto.ts`（手写 AES S-Box/CBC/CMAC）。**这是全仓库最值钱的部分，复刻时直接 install，别重写。**
- **三个硬伤（复刻不可照抄）**：① `/api/check` 无鉴权 + CORS `*` + 任意 host:port = 免费公网端口扫描器（SSRF）；② verbose 模式猴补丁全局 `process.stdout.write`，并发请求结果互相污染；③ `NUXT_MONITOR_INTERVAL` 是死代码，README 说"10 秒"实为 cron 硬编码 10 分钟。另：detection 结果走"结构体→文本→前端正则还原"，双层浪费。
- **MokaKit 侧条件核实**：astro.config 无 adapter（纯静态）；**已有 nginx `/api/` → 127.0.0.1:18800 反代 + `mokakit-counter` systemd 服务**（落盘 /var/lib/mokakit/），再起 18801 的 `mokakit-kms` 成本很低；无 i18n、无图表库；AdSense 已开 `ca-pub-0218164655974877`。
- **结论**：绿色方案（纯静态 GVLK 查询 + 脚本生成，**host 强制用户自填、删除 25 台公共 KMS 服务器列表**）1.5–2 人日，推荐先做；黄色（+自建检测 API）3–4.5 人日；红色（+监控面板）5.5–8 人日**建议放弃**。最大风险不是技术，是 AdSense 政策（封 Publisher ID 影响全站）+ 京 ICP 备案主体合规。
- **关键切分点**：GVLK 密钥与 `slmgr /ipk` 都是微软官方公开/支持的操作，真正越界的是 `slmgr /skms <第三方公网服务器>`。把 host 改成用户必填即从"破解工具"退回"企业 IT 配置生成器"。
- **待办**：等旺财决策走哪档；若做绿色方案，注意 WidgetHost 四步注册 + changelog.ts 补 id + site.ts 工具数 280→281。
