## 路线图不是打卡清单

很多新手一看到「前端路线图」就焦虑：这么多东西，什么时候学得完？其实路线图是**能力地图**，不是考试提纲。它的价值是告诉你「这个方向有哪些关键节点」，而不是逼你按顺序全啃完。

用法建议：**先补主干，再按项目需要补分支**。比如后端先把「语言 + 数据库 + API 设计」吃透，缓存、消息队列用到再学，效率远高于硬背清单。

## 三大方向怎么起步

- **前端**：HTML/CSS → JavaScript → 一门框架（React/Vue）→ 构建工具 → 浏览器原理。类型系统（TS）尽早上。
- **后端**：一门语言 → SQL 与数据库 → REST API → 缓存（Redis）→ 认证授权。消息队列、微服务是中后期。
- **DevOps**：Linux → Docker → CI/CD → Kubernetes → 可观测性。偏运维，但全栈/后端也值得懂基础。

## 编辑精选「最小主干」

不想被清单淹没，就先拿下这几样，足够做出像样的项目：

1. 一门语言（Go / Python / TypeScript）
2. 关系型数据库 + 基本 SQL
3. 一个前端框架 + 构建工具
4. Git 与基础 Linux
5. 一个能部署上线的全流程（本地 → CI → 容器）
