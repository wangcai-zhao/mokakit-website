## 我遇到的具体问题

上周接了个活：合作方发来一份接口文档，里面 200 多行 JSON 全挤在一行，字段名还是驼峰，跟我们系统的下划线风格对不上。更麻烦的是，里面混了 50 多个长度值，有的是米、有的是毫米，得统一成毫米。

我一开始老老实实手敲。改了不到三十行，眼睛就花了，还把两个字段名改串了，后面联调直接崩。那一刻我意识到：这种活不该用人脑干。

## 为什么这事值得自动化

批量格式化、批量换算、批量改名——这三件事的共同点是"规则固定、数量大"。手敲一百次，出错概率接近百分之百，而且错了还不容易发现。

我算了笔账：200 行 JSON 手排 + 50 个值换算 + 大小写统一，认真做怎么也得两小时，还得全程精神紧绷。用工具串起来，十分钟，且不带错的。

## 我是怎么用 WorkBuddy 做的

我把原始文件丢给 WorkBuddy，让它按我的规则处理：先把 JSON 格式化展开，再把单位统一，最后把字段名转成下划线。

但关键一步是——我让它调用专门的工具而不是自己硬算。单位换算交给 [单位换算工具](/tools/unit-convert/)，大小写转换交给 [大小写转换工具](/tools/case-converter/)，JSON 的缩进和校验交给 [JSON 格式化工具](/tools/json-formatter/)。专业工具算得比 AI 拍脑袋准，尤其是单位换算，手算最容易在进制上翻车。

遇到要转成 Base64 的字段，[Base64 编码工具](/tools/base64/) 也顺手用上。

## 中间卡在哪 & 怎么绕过去

第一个坑：WorkBuddy 第一次给我的 JSON 少了个括号，因为它"凭记忆"拼的，没做语法校验。后来我养成规矩——任何 AI 生成的 JSON，落盘前一律过一遍 [JSON 格式化工具](/tools/json-formatter/)，它校验不过就打回重来。

第二个坑：单位换算时它把"米转毫米"算成了乘 100（正确是 1000）。AI 对进制的把握真的不稳，所以我现在单位相关的全丢给 [单位换算工具](/tools/unit-convert/)，不让它自己乘。

第三个坑：驼峰转下划线时，它把 `userID` 拆成了 `user_i_d`。这种边界情况 [大小写转换工具](/tools/case-converter/) 处理得更规矩，直接用它比让 AI 猜强。

## 顺带的几个发现

这套"AI 调度 + 专业工具干活"的组合用熟之后，我把好几个类似脏活都这么处理了：批量改文件名、批量提取 JSON 里的某个字段、批量把 CSV 转成别的格式。

最大的体会是：AI 擅长"理解意图和编排步骤"，但不擅长"精确计算和单位换算"。把后者交给靠谱的小工具，整体又快又稳。

## 你也可以这样用

下次遇到"要改很多、规则都一样"的活，别急着上手。先告诉 AI 你想要什么结果，再明确让它"用专业工具做计算和转换那部分"。你负责定规则，工具负责不出错。

## 常见问题

**Q：直接让 WorkBuddy 算单位不行吗？**
能，但容易在进制、小数点上出错。涉及换算的，我用专门工具兜底，稳妥。

**Q：AI 生成的 JSON 怎么确保没语法错？**
养成习惯：生成完过一遍 JSON 格式化/校验工具，它会在括号、逗号问题上帮你把关。

**Q：批量改名大小写总出岔子？**
用大小写转换工具指定"驼峰转下划线"这类明确模式，比让 AI 自由发挥可靠。
