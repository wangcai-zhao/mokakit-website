## 我遇到的具体问题

上周三在高铁上，运营群里喊"快把昨天的核销数据跑出来发群里"。我手边只有手机，电脑在办公室锁屏。要是以前，只能干等回公司。我其实早把那个报表脚本封装成了 WorkBuddy 技能，但问题在于：我不在电脑前，没人替我按"运行"。我第一次试着在企业微信群里直接发指令时，机器人根本没反应——消息石沉大海，群里多了一条我的自言自语。

## 为什么这事值得自动化

这类"人在外面、活儿在电脑上"的场景，我平均一周撞上三四次：临时拉数、重启某个服务、半夜被叫起来跑对账。每次都是"解锁—开终端—切目录—敲命令—等结果—把结果贴回去"，最少也要 6 到 8 分钟，还经常因为记错参数返工。算下来一个月差不多 20 次、接近两个半小时，而且全是不可预期的打断。

## 我是怎么用 WorkBuddy 做的

核心思路：企业微信自建应用当"遥控器"，WorkBuddy 通过 MCP 当"被遥控的电脑"。我在 WeCom 里建了个自建应用，配了接收消息的回调地址，指向跑在办公室那台机器上的本地转发服务；本地服务再调用 WorkBuddy 的 MCP 接口，把群消息转成一次技能执行。

配置长这样（mcp.json 里一段）：

```json
{
  "mcpServers": {
    "wecom-relay": {
      "command": "npx",
      "args": ["-y", "wecom-mcp-relay@latest"],
      "env": {
        "WECOM_TOKEN": "xxx",
        "WECOM_AES_KEY": "xxx",
        "TARGET_SKILL": "daily-report"
      }
    }
  }
}
```

写这段之前，我先用 [MokaKit 的 mcp 配置生成器](/tools/mcp-config-generator/) 把字段和格式对了遍，少踩一个括号的坑。配置好后，群里发"跑核销"，本地服务收到消息 → 调 WorkBuddy → 跑报表技能 → 把结果回贴群里，全程我手机都不用掏第二次。

## 中间卡在哪 & 怎么绕过去

第一个坑最折磨人：企业微信的回调地址在保存时要做一次"URL 验证"，它会在 5 秒内给你的接口发一个带 echo 串的请求，你的服务必须原样返回那个串，否则后台直接报「URL 验证失败，请检查」。我第一版转发服务是异步回的，慢了 200 毫秒，验证永远过不去。改成同步立即 `res.end(echoStr)` 才过。

第二个坑出在 mcp.json 本身。我手滑把 `args` 写成字符串而不是数组：

```json
"args": "-y wecom-mcp-relay@latest"
```

结果 WorkBuddy 启动 MCP 时把整串当成单个参数塞给 npx，报 `npm error: could not determine executable to run`。用 [MokaKit 的 cron 解析器](/tools/cron-parser/) 的思路类比一下：配置里"数组还是字符串"这种类型错，表面看不出来，一跑就崩。改回数组后秒连。

第三个坑：群消息里 @ 机器人的文本带前缀，比如 `@报表机器人 跑核销`，WorkBuddy 收到的内容是带 @ 全称的，技能匹配不到 `跑核销` 这个关键词，每次都走默认分支。我在转发服务里加了一行去前缀的正则才正常。

## 顺带的几个发现

打通之后顺手捡到几个好处。其一，既然消息能触发一次任务，那配个定时更省事——我用 [MokaKit 的 cron 表达式解析器](/tools/cron-parser/) 把"每个工作日早九点自动跑"翻译成标准表达式，挂上之后连群消息都不用发，报表自己准时躺群里。

其二，那个转发服务本身也能当成一个小技能沉淀下来，以后新接一个平台（比如飞书）只是换层消息适配，逻辑不动——这思路其实就是 [MokaKit 的技能生成器](/tools/skill-generator/) 在讲的事。

## 你也可以这样用

变体场景：你不一定要接企业微信。家里有台常开的 NAS，想用手机随时让它跑个备份或转码，同样的本地转发 + MCP 模式套上去就行。最小可跑版本是：一台不关机的机器 + 一个能接收消息的入口（WeCom 自建应用 / 一个 webhook 接收端都可以）+ WorkBuddy 跑技能。先把"手动在电脑前点一下"这一步省掉，远程化是水到渠成的。

## 常见问题

问：企业微信自建应用和个人微信能打通吗？ 答：不能，自建应用只对企业的通讯录和群有效，个人微信没有这个回调入口。

问：手机发指令安不安全，谁来拦恶意消息？ 答：回调那层必须校验 `WECOM_TOKEN` 和签名，并且只放行白名单群和指定成员，否则谁都能远程让你电脑跑东西。

问：本地转发服务关了会怎样？ 答：群消息收不到，任务不触发，但已经排好的定时任务（走 cron 那路）不受影响，因为那是 WorkBuddy 自己管的。

问：一定要会写代码才能接吗？ 答：消息适配那段要写点胶水代码，但 mcp.json 和技能本身可以靠上面那几个生成器拼出来，不懂 Node 也能搭个能用的雏形。
