## 时钟页层级 bug 修复（MokaKit clock 专题）
- **现象**（旺财反馈）：1) 打开时钟页空白，点「设置→用主题」才恢复；2) 设好背景图后切换其它时钟模式又变空白；3) 页面本该有的正文文字被掩盖/消失。
- **根因**：`src/tools/_shared/ClockStage.tsx` 的 `ClockBackdrop` 背景层与 `ClockSettingsBar` 顶栏用 `position:fixed`，挂在时钟根容器（`position:relative;z-index:10`，内部又含 SSR 时钟内容）里。固定层脱缰成铺满整页的全局层，且被 z-10 上下文抬升，盖住舞台下方的 SEO 正文区（问题 3 确证）。也引发首屏固定层覆盖/合成异常的「空白」。
- **修法（纯 CSS 定位，无逻辑改动）**：
  - `ClockBackdrop` 三分支（图像/纯色/主题）与顶栏 `position:fixed` → `position:absolute`，锁死在 `#ck-immersive-stage` 内（stage 有 `overflow:hidden` 裁掉溢出，滚动后自然让位正文）。
  - `ClockImmersiveLayout.astro` 舞台加 `isolation:isolate`，SEO 区加 `position:relative;z-index:1` 兜底。
  - `world-clock/Tool.tsx` 时钟根容器补 `minHeight:100vh`（其它三种内容自带），保证背景铺满首屏。
  - 时钟内容保持 `z-index:10` 永远在背景之上。
- **验证**：`astro build` 成功（408 页，无报错）。产物核对：stage `isolation:isolate`、背景层 `position:absolute;inset:0px;z-index:0`、顶栏 `position:absolute;top:0;...z-index:50`、全文 `position:fixed`=0。
- **已部署上线**（旺财指令「推」）：复用最新 dist（跳过重复 build 避卡死），走等价 deploy 原子切换 + `nginx -t && reload`（不动 SSL）。流程全过：占位域名快检 ✓、407 个 index.html、四时钟页均在、UPLOAD_DONE、RELOADED。
- **线上核验**：ssh curl 抓 www.mokakit.com/tools/digital-clock/ → 舞台 `isolation:isolate` ✓、全文 `position:fixed`=0 ✓、背景层 `position:absolute;inset:0px;z-index:0` ✓、顶栏 `position:absolute;top:0;...z-index:50` ✓、SEO 区 `position:relative;z-index:1` ✓、HTTP 200 ✓。修复真实生效。
- **注意**：构建如遇卡死，先停进程（本环境 `mv/rm` 被「安全删除」拦截会失败，勿用），重跑 astro build 通常即过（已验证）。

## 时钟空白根因二次定位 + hydration 修复
- **线上反馈（旺财实测）**：第 3 项（正文被盖）已解决；第 1、2 项（打开空白/切模式空白）**仍在**。说明空白不是 CSS 层级问题，是时钟组件初始渲染失败。
- **确证手段**：ssh curl 抓线上 digital-clock SSR 产物 → 时钟内容（tabular-nums / Asia/Shanghai / 摩卡时钟 / min-height:100vh）**完整存在**，image 背景层在默认 theme 下未出现。SSR 正常 ⇒ 问题在**客户端 hydration**。
- **真根因**：`useClockSettings` 的 `useState` 初始化函数直接读 `localStorage`。SSR 时无 localStorage → 用 default（theme 模式）；客户端首帧读到用户存的 image 背景 → 二者首帧 DOM 不一致 ⇒ **Preact hydration mismatch**，整块时钟 island 在 hydration 时被重渲染异常（空白）。点「用主题」改 state 触发一次正常 re-render 才恢复。症状 2「切模式整页重载变空白」同理（换页即重新 hydrate）。
- **修法（客户端 hydration 规范化）**：把 `localStorage` 读取从 `useState` 初始化移出，改到挂载后的 `useEffect`（仅首帧读一次）；`useState` 初始统一用 `DEFAULT_CLOCK_SETTINGS`（与 SSR 一致）。用户持久化设置随后异步应用，首屏永远先正常显示默认主题，再无缝切到用户背景。同反模式也修了 `world-clock/Tool.tsx` 的城市列表 `useState(() => load())` → 初始 DEFAULT_TZ + 挂载后 effect 读取。
- **验证**：`astro build` 成功（408 页，0 报错）。复用含修复的 dist 走等价 deploy 原子切换 + reload 上线（域名快检 ✓、UPLOAD_DONE、RELOADED）。
- **旺财浏览器实测（01:20 反馈）：第 1、2 项空白已彻底解决，本次修复闭环成功** ✅。副作用（首屏几百毫秒默认主题再切背景）可接受、未投诉。时钟页三类症状（空白×2 + 正文被盖）至此全部修复完毕。
- **关键经验**：Astro `client:load` 组件，凡首帧依赖 `localStorage`/`window` 的 state，**必须用「useState 初始化用 safe default + useEffect 内读存储」模式**，否则 SSR/CSR 首帧不一致必踩 hydration mismatch 白屏。
