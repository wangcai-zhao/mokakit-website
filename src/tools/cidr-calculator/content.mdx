## CIDR 子网计算器怎么用

划子网手算很折磨人：要把掩码转二进制、把 IP 按位与、再数清头尾能分给主机的地址。把网段按 192.168.1.0/24 这样的格式填进输入框，工具会一次性给出网络地址、广播地址、子网掩码、通配符掩码、二进制掩码、可用主机范围与主机数。反过来也成立：只填 IP 地址，再填 255.255.255.0 这样的掩码，它能换算出等价的 CIDR 前缀。所有运算本地完成，不联网。

## 这个工具能做什么

- 解析 CIDR 网段，支持 /0 到 /32 全范围前缀
- 算出网络地址、广播地址、子网掩码与通配符掩码
- 给出可用主机范围，即首可用 IP 到末可用 IP
- 统计可用主机数与总地址数
- 展示掩码对应的二进制形式，方便对照
- 用 IP 加子网掩码反算 CIDR 前缀，并校验掩码是否合法

## 怎么使用（输入说明）

1. **IP 地址 / CIDR 网段**：填 192.168.1.0/24 这种带斜杠的写法；也可只填纯地址，配合下面的掩码使用。
2. **子网掩码（选填）**：填 255.255.255.0 这类掩码即可反算前缀，注意不要和斜杠前缀同时填。
3. **快捷示例**：点一下自动填入常见网段，方便对照结果。
4. 输入变化即时出结果，格式有误会用中文提示具体错在哪。

## 背后的原理/规则

IPv4 地址本质是 32 位二进制数，点分十进制只是方便人读。前缀长度表示掩码里连续 1 的位数，/24 就是 24 个 1 加 8 个 0，即 255.255.255.0。

网络地址由 IP 与掩码按位与得到，代表网段本身；广播地址由网络地址或上掩码的反码得到；掩码的反码又称通配符掩码，常用在防火墙与路由器的访问控制列表里。可用主机数默认是总地址数减 2，因为网络地址与广播地址不能分配给设备。

但有两个例外：/32 只有一个地址，常见于回环地址、主机路由或安全组精确匹配，没有广播地址概念；/31 传统算法下可用主机数为 0，RFC 3021 规定它用于点对点链路时两端各占一个地址，所以可用主机数是 2。

## 计算实例

以 192.168.1.0/24 为例。掩码为 255.255.255.0，二进制是 11111111.11111111.11111111.00000000。网络地址 192.168.1.0，广播地址 192.168.1.255，通配符掩码 0.0.0.255。可用主机范围 192.168.1.1 到 192.168.1.254，可用主机数 254，总地址数 256。

再看 10.0.0.0/8：掩码 255.0.0.0，广播地址 10.255.255.255，可用主机数 16777214。以及 192.168.1.1/32：只有一个地址，工具会提示这是单主机路由，可用主机数为 1。

## 常见问题 FAQ

**Q：可用主机数为什么比总地址数少两个？**

A：传统子网划分里，网段最小地址是网络地址，用来标识网段本身；最大地址是广播地址，用于向网段内所有主机发包。这两个地址不能分配给具体设备，所以可用主机数等于总地址数减 2。/31 和 /32 属于例外情况，前者按 RFC 3021 两个地址都可用，后者只有一个地址。

**Q：/31 和 /32 这两个特殊前缀该怎么理解？**

A：/32 网段里只有一个地址，通常用于路由器回环接口地址、主机路由或安全组规则里的精确匹配，不存在广播地址。/31 传统上网络地址与广播地址就占满了两个地址，导致没有主机可用，RFC 3021 规定它用于点对点链路时两端各用一个地址，因此可用主机数为 2。

**Q：输入 IP 加子网掩码能算出 CIDR 前缀吗？**

A：可以。主输入框填 IP，下方掩码框填 255.255.255.0 这样的点分十进制掩码，工具统计掩码中连续 1 的个数换算出前缀长度，再按同样方式算出网络地址与主机范围。如果填的掩码不是前面全是 1、后面全是 0，属于非法掩码，工具会明确提示。
