### 两个重要认知修正（问题比想象中少）
1. **空分类不会暴露 404**：`Header.astro` 用 `activeCategoryIds` 过滤，只显示有工具的分类；分类页 `getStaticPaths` 仅生成有工具的分类 → 空分类（calc/life/fun）不进导航、不被 sitemap 收录。所以不是"用户点进去 404"，只是配置里挂着 3 个暂无工具的分类。
2. **配色已基本成品化**：之前的"待打磨"诊断是基于更早版本；当前 `global.css` 已实现昨晚定的方向且注释完整，大改不必要，上线前做一次浏览器亮/暗走查即可。

## 二、问题清单（分级，带依据）

### P0 · 上线阻塞（外部 / 手动，必解）
- **P0-1 部署密钥未绑定**：`mokakit_deploy` 公钥未在腾讯云导入并绑定实例 → `deploy.sh` 无法 SSH 连服务器 → 占位页/正式站都上不了。**唯一硬阻塞**，责任在旺财手动。
- **P0-2 ICP 备案审核中**：外部时间，约 7 工作日（预计 8-10 ~ 8-13 出）。生产上线必须等它放行。
- **P0-3 部署链路未真实验证**：服务器重置后 `deploy.sh` / `server-setup.sh` **从未真跑过**，上线时有翻车风险。建议占位阶段先跑一次 `--setup` 验证整条链路（nginx 版本、路径、证书申请）。

### P1 · 上线前内容 / 质量（不阻塞，建议上线前收口）
- **P1-1 空分类处理**：3 个无工具分类挂着显冗余。建议二选一：① 补 1-2 个高频纯前端工具（日期计算 / 贷款 / BMI → calc；生活类需静态数据）② 从 `categories.ts` 移除预留（保留注释说明将来扩展）。优先级中低。
- **P1-2 配色走查**：代码已成品，上线前真实浏览器亮/暗模式各扫一遍，确认对比度（尤其 primary 文字、聚焦圈）。
- **P1-3 SEO 基础补全**：sitemap 有了，但还缺 `robots.txt`（允许抓取 + 指向 sitemap）、`og:image`（社交分享图）、各页 `title`/`description` 唯一性复查、全页 JSON-LD 结构化数据是否齐。
- **P1-4 占位期合规**：备案通过前只用 `icp-pending` 占位页，正式内容不对外 —— 已规划正确，保持。

### P2 · 内容扩展（增长，上线后主推）
- **P2-1 好站导航扩到 100+**（`/sites` 框架已就绪，旺财定的下一阶段）。
- **P2-2 AI 比价数据扩充**（更多模型/视觉平台，价格持续人工校对）。
- **P2-3 工具补量对标 it-tools 60+**（现存 31）：纯前端可补 —— 颜色调色板生成、密码泄露离线检测、二维码扫描、Base58、slugify、随机数、批量哈希、图片压缩、阅读时长估算等。
- **P2-4 长尾词内容**：为高频具体查询铺子页（SEO 命脉），注意避免 thin content（N×N 全排列）。

### P3 · 运营 / 增长（上线后）
- **P3-1 访问统计接入**（百度 / GA，看行为反向优化工具）。
- **P3-2 外链建设 / 主动提交搜索引擎**。

## 五、关键依赖与风险

- **备案可能延迟 / 被打回**：需改备案信息则顺延；占位页阶段不影响进度。
- **部署脚本首次运行环境差异**：nginx 版本、路径、证书申请（acme.sh）可能遇坑，故 `--setup` 先验证。
- **服务器规格**：2核2G，流量上来需监控；纯静态 + 本地计算为主，压力可控。
- **价格数据维护成本**：AI 比价是人工校对快照，需持续投入，避免「大而糙」假数据。
