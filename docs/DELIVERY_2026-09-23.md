## 四、SEO 优化

### 4.1 结果对比

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 存在 SEO 问题的页面 | **39** | **0** |
| 描述过短（拿不满摘要位） | 26 | 0 |
| 描述过长（被截断） | 10 | 0 |
| 多 h1 页面 | 3 | 0 |
| HTML 平均体积 | 约 91.4 KB（按瘦身量反推） | **63.0 KB** |
| 单页雪碧图内联 | 106 个 symbol（约 33 KB） | 仅本页用到的 6-15 个 |

### 4.2 具体措施

**元信息**

- 分类页 / 好站分组页 / 智能体页的 meta description 由「直接引用短副标题」改为拼装 80-160 字完整描述，一次改动覆盖 19 个页面。
- 修正智能体详情页的复制粘贴 bug：描述里把 AI 智能体写成了「站点」，用户看到的摘要和实际内容不符。
- 精简 6 个超长描述（gitignore-gen 225 字、udi-generator 185 字等），避免被搜索引擎截断。
- 单位换算长尾子页模板加长，一次修复全部长尾子页。
- `title` 长度修正（`about` 页此前仅 7 字）。

**URL 与索引**

- `robots.txt` 修正反模式：原先 `/search/` `/go/` 既 Disallow 又 noindex，导致爬虫读不到 noindex（页面可能被索引成无描述结果）。现在允许抓取、交给页面 noindex meta 处理。
- 补 `/search/` 页面的 `noindex`（此前漏写，放宽 robots 后会变成可索引的垃圾页）。

**Sitemap**

- `lastmod` 由「每次构建全站刷新」改为真实更新时间：工具页取 `meta.ts` 的 `updatedAt`，内容页一次性从 git 取该文件的最后提交日期。全站 500+ 页不再「假装每天都更新」，节省抓取预算。
- `priority` 由页面深度改为按工具自身权重映射（0.4-0.9），首页 1.0。
- 抽查验证：11 个新工具的 lastmod = 2026-09-23、priority = 0.7，全部正确。

**结构化数据**：588 页全站覆盖 WebSite/Organization，502 页有面包屑，487 页有 WebApplication + FAQPage，12 篇 Article，JSON-LD 解析零错误。

**性能**

- 新增 `scripts/optimize-sprite.mjs`：产物阶段删除每页用不到的 `<symbol>`，累计减少 **16.6 MB**、平均 **28.4 KB/页**。带安全护栏：检测到 JS 动态拼接 sprite id 的页面自动跳过。
- 修复 `seo-audit.mjs` 的灾难性回溯正则（`(?:"[^"]*"|'[^']*'|[^>])*`），配合 head 片段提取，审计从 300 秒超时降到秒级。
